# 确定性的历史处理工作量探针

Status: implemented
Translation: current

[English](2026-10-15-history-work-harness.md)

## 摘要

守护进程可能在主线程上花费数秒处理会话历史。本诊断分别检查当前源码中的
两个机制：重复的子代理线性查找，以及子代理批次回退到整个历史的写入路径。
探针以合成数据执行真实源码片段，通过操作次数避免依赖宿主负载的性能阈值。
结果证明工作量增长和路由行为，不证明实际阻塞时长或线上在线状态故障的原因。

## 运行与来源

```sh
node scripts/probe-history-work.mjs
```

使用支持 `stripTypeScriptTypes` 的 Node 22.14+，或仓库支持的更新运行时。
无需安装依赖。探针读取当前检出的三个源码文件，并输出 SHA-256 哈希。
仅删除 TypeScript 类型和声明的 export 修饰符，不改写函数体。
不支持的源码布局会明确失败。VM 不是安全边界，只能执行可信源码。
探针不会导入或启动应用。

记录的源码基线为 `a06a69f3e96eec68751ebd4df1d050cbbc4f1cea`。
合成测量结果保存在 `scripts/history-work-results.json`。

## 假设与独立执行

预测：历史由 16 轮增至 256 轮时，末项查找工作量增加十六倍；重复 32 个
子代理事件会再乘以 32。32 个子代理批次会读取整个历史，而普通文本对照走
定向写入路径。若查找工作量恒定或子代理采用定向路由，则假设被证伪。
父代理设计实验，独立的 `alchemist` 执行，未修改文件或访问线上服务。

实测检查项数为 128、2,048 和 65,536。32 个子代理批次分别请求导出
512 和 8,192 轮。文本对照没有完整导出，执行了 32 次定向写入。
预建索引对照无需再次扫描便返回相同结果；它仅验证实验敏感度，不是修复方案。

## 边界与限制

路由实验执行真实的 `createSessionAgentWrites`，但以无操作替代内容修改，
并观测注入的写入边界。查找实验独立执行 `findRun`。
真实 `readStored` 调用的是注入的 `toJSON` 边界，不执行 WASM、SQLite 或
Immer。因此这不是端到端 ACP 重放，也不是延迟基准测试。

结果说明定向优化之外仍存在整个历史的处理路径，不证明死锁、线程数量无界
增长或具体网络错误。后续产品修复仍需真实存储边界的行为测试和性能分析。
本分支不修改产品代码，也不包含真实对话或守护进程日志。

旧在线状态队列探针针对旧传输实现，不能据此推断当前原生 Effect 实现仍有
同一缺陷。独立的文件锁探针仅说明锁的边界，结论不与本探针合并。
